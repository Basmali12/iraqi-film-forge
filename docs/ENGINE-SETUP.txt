دليل إعداد إدارة محركات Modal — بدون نشر أو تشغيل مدفوع
2026-10-27

المشروع: Basmali12/iraqi-film-forge
الفرع المحلي: codex/modal-engine-management

1. المتطلبات المحلية
Node.js 24+ (النسخة المفحوصة 24.14.1)، وPython 3.13.17 محلياً.
صورة الاستدلال المستقبلية تستخدم Python 3.12 وTorch 2.9.1+cu128.

من PowerShell، داخل مجلد المستودع:
  npm ci
  & 'C:\Users\hp\AppData\Local\Programs\Python\Python313\python.exe' -m venv --system-site-packages .venv-engine
  & '.\.venv-engine\Scripts\python.exe' -m pip install -r engine/requirements-local.lock -r engine/requirements-transfer.lock -r engine/requirements-test.lock

الاعتماديات المحلية الصغيرة فقط؛ لا يثبت هذا Torch ولا ينزل الأوزان.
البيئة المعزولة أُنشئت وفُحصت في هذا التنفيذ. لم تُغيّر بيئة Python العامة.
يكتشف الخادم .venv-engine تلقائياً، ويمكن تعيين ENGINE_PYTHON لمسار Python موثوق آخر.

يحفظ دليلاً منقّحاً في docs/read-only-inspection.json، ويتوقف إذا اختلفت هوية الحساب عن basm1998ali.

3. إنشاء مسؤول الخادم — ينفذه المالك محلياً، وليس بإرسال كلمة مرور داخل المحادثة
استخدم حساب Windows نفسه الذي سيشغّل الخادم:
  $privatePassword = Read-Host 'اختر كلمة مرور مسؤول قوية، 14 حرفاً على الأقل' -AsSecureString
  $env:ENGINE_ADMIN_PASSWORD = [System.Net.NetworkCredential]::new('', $privatePassword).Password
  $env:ENGINE_ALLOW_PAID_ACTIONS = 'NO'
  npm run engine:setup
  Remove-Item Env:ENGINE_ADMIN_PASSWORD
  $privatePassword.Dispose()

لا يطبع الأمر كلمة المرور ولا مفتاح التشفير. يُحفظ تجزؤ scrypt لكلمة المرور.
على Windows يولَّد مفتاح AES عشوائي ويُغلف بـDPAPI/CurrentUser داخل .engine-data/master-key.dpapi.
هذا الملف مشفر، ولا يحتوي مفتاحاً نصياً. اختُبر DPAPI محلياً دون طباعة قيمة المفتاح.
على Linux، احقن ENGINE_MASTER_KEY (32 بايت بصيغة base64) من مدير أسرار الخادم.
لا تضعه في الواجهة أو Git أو السجلات. لا تغيّر المفتاح لقاعدة موجودة دون إعادة تشفير آمنة.
فقدان مفتاح الخادم/ملف DPAPI أو تشغيله بهوية Windows أخرى يمنع فك بيانات الاتصال.

4. HTTPS وحفظ البيانات
استقبال كلمات المرور وتوكنات Modal وHF يتطلب صفحة HTTPS وخلفية HTTPS متحققة.
واجهة ثابتة وحدها، أو مجرد HTTP محلي، لا تكفي. يوجد حاجز في المتصفح وآخر بالخادم.
لا تتجاوز تحذير شهادة المتصفح. استخدم شهادة موثوقة أو reverse proxy موثوقاً.

عند توفر شهادة موثوقة (لا توجد شهادة مُنشأة ضمن هذا العمل):
  $env:HOST = '127.0.0.1'
  $env:PORT = '3443'
  $env:ENGINE_ORIGIN = 'https://localhost:3443'
  $env:ENGINE_ALLOWED_ORIGINS = 'https://localhost:3443'
  $env:ENGINE_TLS_CERT = 'ABSOLUTE_PATH_TO_TRUSTED_CERTIFICATE'
  $env:ENGINE_TLS_KEY = 'ABSOLUTE_PATH_TO_PRIVATE_KEY'
  $env:ENGINE_ALLOW_PAID_ACTIONS = 'NO'
  npm start

ثم افتح https://localhost:3443/engines.html بعد ضبط المسارات الفعلية.
لا تضع محتوى المفتاح الخاص في الأوامر أو Git. الملفات .pem/.key/.crt مستثناة من Git.
إذا أنهى proxy محلي TLS، اضبط ENGINE_TRUST_PROXY=loopback فقط مع proxy يكتب X-Forwarded-Proto بنفسه.
لا يثق الخادم بهذا الرأس من عنوان خارجي. لا تفعّل ذلك خلف وسيط غير موثوق.

ENGINE_DATA_DIR يحدد قرصاً خاصاً ودائماً للخادم، مستقلاً عن أي حساب Modal.
الافتراضي .engine-data مستثنى من Git. يحتوي SQLite والنتائج والمراجع المشفرة/المحمية حسب نوعها.
توكنات الحسابات مشفرة بـAES-256-GCM؛ ملفات الفيديو والمراجع تحت صلاحيات مستخدم الخادم.
خصص هوية خدمة وصلاحيات ملفات خاصة، ونسخاً احتياطية مشفرة. لا تنسخ SQLite منفرداً أثناء وجود WAL نشط؛
استخدم نسخ SQLite السليمة أو أوقف الخادم بأمان ثم انسخ مجلد البيانات ومفتاحه المحمي.
لا تنقل ملف DPAPI إلى هوية أخرى وتفترض قابليته للفك. يجب إدارة نقل مفتاح الخادم بصورة آمنة.

5. GitHub Pages والخلفية المنفصلة
الخيار المفضل: خدمة الواجهة والإدارة وAPI من النطاق الخاص الموثوق نفسه، مع HTTPS.
يمكن أن يهيئ npm run build عنوان API عاماً فقط من ENGINE_PUBLIC_API_ORIGIN.
مثال غير منفذ: https://api.your-owned-domain.example (أصل فقط، دون مسار أو بيانات اعتماد).
لا ينسخ البناء أية ملفات من engine/ أو .engine-data إلى dist/.
حقل عنوان الخلفية في صفحة الدخول، وحقل خلفية Modal المستقل في إعدادات المخرج، يحددان العنوان بالجلسة فقط.

إذا اختيرت خلفية عبر نطاق آخر، اضبط ENGINE_ALLOWED_ORIGINS إلى قائمة أصول HTTPS الموثوقة بدقة.
الجلسة الافتراضية Secure/HttpOnly/SameSite=Strict. الاستخدام بين مواقع مختلفة يحتاج قرار إعداد صريح
ENGINE_COOKIE_SAME_SITE=none؛ تبقى حماية CSRF وقائمة الأصول إلزاميتين، وقد تمنع المتصفحات كوكي الطرف الثالث.
لا توسع CORS إلى *، ولا تفترض أن مسارات مستودعات GitHub Pages مستقلة أمنياً: المشاريع تحت
basmali12.github.io تشترك في الأصل نفسه. استخدم نطاقاً خاصاً/إدارة بنفس الأصل قبل نشر صلاحيات المسؤول.
وكيل دردشة OpenAI القديم يستعمل ALLOWED_ORIGINS بصورة مستقلة عن ENGINE_ALLOWED_ORIGINS؛ اضبطه لأصلك الموثوق عند استخدامه.
لم تُضبط أصول إنتاج أو ملفات كوكي مشتركة، ولم يُنشر أي شيء في هذا التنفيذ.
مشاريع المتصفح الحالية لم تُنقل أو تُمسح؛ تعديل النطاق يحتاج استيراداً/تصديراً مقصوداً لبياناته، لا مسحاً.

6. الربط والفحص — لا GPU
بعد دخول المسؤول عبر HTTPS:
- «ربط الحساب الأساسي المحلي» يقرأ profile الموجود على الخادم ويتحقق من basm1998ali فعلياً.
- بديله: الحقلان Modal Token ID وModal Token Secret ثم «ربط الحساب والتحقق».
- لا ترسل أي توكن في المحادثة. لا يعود ID أو Secret من API بعد الحفظ.
- إضافة basm1998ali عبر الحقلين تجعله المصدر الأساسي للقراءة فقط.
- ربط حساب جديد لا ينشئ Volume أو GPU. لا تُنشأ نسخة حساب بمجرد معرفة الاسم.
- جلب معلومات الأساسي/فحص الاتصال/حفظ اختيار الحساب والكرت عمليات SDK للقراءة فقط.
- النطاق التشغيلي الحالي بيئة main في كل حساب؛ لم تُفحص البيئات الأخرى.
- الكرتان فقط RTX-PRO-6000 وL40S. توافرهما الفوري وحدود الحساب لا يمكن ضمانها بالفحص المجاني.

7. خطة تجهيز الحساب الثاني — التنفيذ مقفل الآن
الخيار المعتاد: مصدر Volume الأساسي -> خادم staging خاص -> Volume الوجهة، بواجهات Volume العامة.
تُفحص الأحجام وREADY مجاناً. لا يُفترض أن Volume قابلة للمشاركة بين حسابين.
الفحص الكامل SHA قد يقرأ نحو 66.21GiB خلال العملية المعتمدة، وقد تنطبق رسوم نقل.
إذا اكتُشف تلف خارج قائمة الملفات المعتمدة، تتوقف العملية وتُنشأ خطة جديدة قبل نقل إضافي.
تُحفظ الملفات المكتملة في الوجهة، وتُفحص بصماتها، ولا يعاد نقل السليم عند استكمال معتمد لاحقاً.
SDK لا يقدم كتابة أجزاء قابلة للاستكمال داخل ملف Volume؛ يُستأنف على مستوى الملفات المكتملة.
يلزم قرص staging خاص بحجم أكبر ملف + 1GiB: نحو 40.13GiB حرة. يجري الفحص قبل إنشاء Volume.
المصدر الرسمي البديل يستعمل huggingface_hub 1.33.0 وتوكن HF خاصاً بالوجهة، مع مراجعة الترخيص والتصاريح.
فحصه الأول dry_run=True لبيانات الملفات فقط، دون تنزيل النموذج. لا يُحفظ login عالمي لـHF.
استكمال التنزيل الجزئي يعتمد على دعم عميل HF؛ الرفع إلى Volume ما يزال على مستوى الملف.
لا يُنقل ltx25-hf-read أو أي سر من الأساسي. الاستدلال offline لا يحتاج HF_TOKEN داخل حاوية GPU.
بعد النجاح تُكتب READY.json وRUNTIME.json في الوجهة فقط. هذا يعني جاهزية الملفات، لا جاهزية GPU.

8. التشغيل المدفوع لاحقاً — ليس أمراً منفذاً الآن
يبقى ENGINE_ALLOW_PAID_ACTIONS=NO افتراضياً. لا تغيّره قبل موافقة المالك المنفصلة.
حتى عند تفعيله، يلزم لكل عملية quote حديث مدته خمس دقائق وتأكيد «أوافق على التكلفة».
يُحجز job/idempotency داخل معاملة SQLite قبل أي استدعاء مدفوع.
لا fallback ولا إعادة توليد تلقائية. يوجد حد عالمي لمهمة GPU نشطة واحدة، max_containers=1 وmin_containers=0.
«تشغيل المحرك» يحمل البرومبت نفسه فقط؛ بعد الجاهزية ينتظر حتى 15 ثانية مخططاً، ثم يُغلق إن لم يُطلب المشهد.
«توليد المشهد» عند الطلب أفضل لتجنب خمول مدفوع؛ يُوقف App بعد المشهد.
توليد مشهد من المخرج يستخدم الاختيار المحفوظ، ويطلب موافقة تكلفة لكل مشهد 10 ثوانٍ.
المشهد الناجح لا يعاد إرساله. الفشل المؤكد مع توقف مثبت ودون MP4 يسمح بخطة إعادة جديدة تحفظ المحاولة السابقة.
النتيجة المجهولة لا تعاد؛ استعمل فحص الحالة والاستعادة أولاً.
زر الإيقاف يلغي المهمة فقط بعد تأكيد المستخدم، ويتحقق من App وحاوياته، دون حذف الأوزان.
إيقاف الانتظار محلياً أو انتهاء مهلة ليس ضمان فاتورة أو إثباتاً كافياً لإيقاف السحابة.

9. مراقبة النتائج والحدود
التقدم مأخوذ من أحداث فعلية/بايتات أو خطوات denoiser، مع مؤشر غير محدد حين لا يوفر SDK قياساً موثوقاً.
ETA الكلي غير معروف حالياً؛ لا توجد بيانات معيارية لهذا المسار الجديد تسمح بتوقع موثوق.
إجمالي spans المتداخلة لا يساوي مجموع الزمن الكلي؛ لا تجمعها جمعاً ساذجاً.
التكلفة المسجلة تقرأ من billing report للتطبيق حين تتوفر، وقد تتأخر وتتغير ولا تشمل كل رسوم الصورة/Volume/النقل.
حد المهمة والحارس الشهري لا يعدلان فوترة Modal، ولا يغطيان الاستضافة أو الرسوم المجهولة.
الـMP4 والتقرير ولقطة الإطار الأخير تُحفظ بالخادم. تعطّل تسجيل محلي لا يبرر إعادة توليد ناجح.
«فحص الحاويات والمهام» يستعيد إيصال MP4 المحلي إن كان قد وصل وتحقق hash، دون GPU جديد.
إلغاء ربط حساب يمحو أسرار ربطه محلياً؛ لا يلغي توكنه لدى Modal ولا يحذف Volume ولا رسوم تخزينها المستمرة.

10. حدود التحقق قبل النشر
لم تختبر نقل الأوزان الحقيقي أو تشغيل الخدمة الجديدة على GPU أو إلغاء حاوية حقيقية جديدة، احتراماً للمنع.
ثبات الشخصيات/الصوت بين المشاهد يحتاج فحص فيديو فعلي. يوجد I2V فعلي من آخر إطار، وليس ادعاء Latents مستمرة بين وظائف مستقلة.
المرجع الأول يشرط أول إطار؛ بقية المراجع محفوظة لاستمرارية المشروع ولا يحق الادعاء بأن جميعها conditioning متزامن.
API التحقق والتخزين والتوليد تعتمد SDK العام. تعداد التطبيقات/الحاويات وإلغاء التطبيق وقراءة بياناته تستعمل
طبقة توافق داخلية معزولة من SDK 1.6.2؛ ليست واجهة عامة مستقرة ويجب مراجعتها عند الترقية وقبل اعتماد النشر.
لا تعرض لوحة الاختبار البصري كإثبات سحابي. tests/visual-server.mjs منفصل وموسوم بوضوح، ولا تستعمله للإنتاج.
