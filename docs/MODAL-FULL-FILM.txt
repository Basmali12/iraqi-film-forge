Implemented
1. film.html keeps the legacy HeyGen default and adds an explicit Modal/LTX provider.
2. Free rules-based chronological splitting of the complete user-written story.
   30–600 seconds, multiples of 10: 180s = 18 scenes; 300s = 30 scenes.
   A scene gets its own events/dialogue. Missing story detail causes a clear refusal,
   not repeated events or invented dialogue. This is not a semantic LLM screenwriter.
3. Optional stable cast/voice instructions; no claim of verified face/voice locking.
4. Uses only an explicitly prepared engine of the selected account/GPU.
   No implicit new GPU allocation, GPU fallback or automatic paid retry.
5. Each new scene needs a real server quote and explicit individual cost consent.
   Film-plan approval alone never dispatches a paid scene.
6. First three scenes require human quality review before proceeding to later scenes.
7. Durable ambiguous status precedes submit; job IDs persist immediately after acknowledgement.
   Completed clips are not regenerated when resuming. Lost acknowledgements stop the flow.
8. Backend resolves previousSceneId to a completed scene in the same project and its saved
   last-frame file; private controller pipe passes this reference to the existing GPU session.
9. Persistent StoryEngine accepts a fresh unique conditioning image for each request and
   clears prior conditioning on unconditioned requests. Transformer reuse remains intact.
10. Native ImageConditioningInput.at(frame=0) is supplied to LTX run preparation and denoising.
    Audit stores conditioning count and SHA256 of the actual input image; GPU verification pending.
11. Original clips have project-scoped IndexedDB keys; recursive FFmpeg assembly keeps audio.
    New Modal plans archive previous project metadata without deleting prior clips.

Important limitations
- Continuation is last-frame image-conditioned clips followed by assembly, NOT native
  cross-clip joint video/audio latent continuation. Motion, voice, lips and identities may drift.
- Browser supervises scene sequencing and merging. Closing the page pauses scheduling;
  an already dispatched cloud scene may continue. Resume polls the saved job ID.
- No whole-film fixed cost is asserted. Each scene is quoted before execution; actual costs
  remain null until supplied by the provider. Paid engine idle time may also be billed.
- Runtime source changes may require new image layers on a later approved engine start;
  no image build was performed here. Existing saved model weights remain unchanged.
- No paid three-scene continuity test, native conditioned GPU inference, long-film merge,
  live PostgreSQL migration or production deployment was performed in this task.
