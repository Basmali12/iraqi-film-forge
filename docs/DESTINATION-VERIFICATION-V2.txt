# إصلاح نقل أوزان الحسابات — V2 / 2026-10-27

الحالة: منفذ ومختبر محلياً، ولم يُنشر على HostHatch أو Modal بعد. لم يتم حذف أوزان أو إعادة نقلها أو تشغيل GPU بهذا الإصلاح. لا نقول إن تحسين السرعة السحابي مثبت قبل اختبار حقيقي منفصل.

تجربة الاستخدام المطلوبة:
إضافة حساب → إدخال Modal Token ID وModal Token Secret → فحص وتخزين مشفر بالخادم → عرض خطة التجهيز وكلفتها → موافقة واحدة على عملية التجهيز → تجهيز الأوزان والتحقق تلقائياً → حفظ الحساب واختياره من القائمة → تشغيل أو إيقاف المحرك بنفس الواجهة.
اختيار الحساب لا يبدأ GPU. التشغيل المدفوع يظل يحتاج موافقته. الكرت الافتراضي RTX PRO 6000، والبديل L40S؛ لم تتغير جودة الفيديو أو الصوت أو الأوزان.
أزرار التشخيص (فحص الأوزان/اختبار 64KiB/تجديد التفويض) انتقلت إلى الإعدادات المتقدمة محلياً لتبقى الواجهة الرئيسية بسيطة.

السبب الذي عولج في الكود:
كان العامل الأساسي يرفع الملف ثم يعيد قراءته كاملاً عبر Volume.read_file لحساب SHA256، بينما الواجهة لا تتلقى عداداً أثناء هذا الفحص. قياس التجربة السابقة أظهر نحو 12MB/s، فلا تكفي مهلة ساعة لكل 66GiB بهذا المعدل. تغيير GPU أو حذف الملف لا يصلح هذا المسار.

المسار الجديد:
1. حجز job دائم قبل أي إرسال. نشر/إعادة استخدام عامل تحقق CPU خاص بـVolume حساب الوجهة فقط بعد الموافقة المعروضة.
2. العامل في الوجهة يركب Volume للقراءة فقط ويحسب SHA256 باستخدام فتح الملفات محلياً، مع تقدم بايتات فعلي وإلغاء.
3. العامل الأساسي يتجاوز الملفات المثبتة بالبصمة، وينسخ الناقص المعتمد من مصدره المركب للقراءة فقط. لا تمر الأوزان بقرص HostHatch.
4. فحص نهائي قرب Volume الوجهة. لا ينشئ العامل الأساسي READY.json إلا بعد مطابقة أسماء الملفات الخمسة وأحجامها وبصماتها ونسخة النموذج. قراءة READY.json الصغيرة وحدها تمر بالـSDK.
5. إذا ظهر تلف خارج نطاق الخطة، تتوقف العملية وتطلب خطة جديدة قبل الاستبدال. لا حذف للأوزان الأصلية ولا إعادة محاولة آلية.

الأمان والتوقف:
- توكن المصدر لا يرسل إلى حساب الوجهة. توكن الوجهة محفوظ مشفراً بالخادم ويمر عبر Secret مؤقت إلى العامل الموثوق، وليس معاملات الدالة أو السجلات.
- كل مرحلة تحقق لها حجز دائم ومعرف مستقل؛ فقدان الرد لا يعيد spawn.
- الإلغاء يتابع المصدر والوجهة كليهما. لا cloudStopped=true قبل انتهاء الاستدعاءات وصفر حاويات في الجهتين. الاستدعاء المجهول يبقى uncertain.
- موارد CPU فقط: 2 CPU / 4GiB لكل عامل، min_containers=0، retries=0، scaledown_window=2.
- العامل الجديد يستخدم دالة مصدر عامة، لا closure متسلسلة ببايتكود Python؛ يتجنب اختلاف Python 3.13 المحلي عن صورة Python 3.12.
- fingerprint البروتوكول تغيّر، لذلك Backend الجديد يرفض العامل القديم إلى أن يُحدّث النشر. نشر العامل يرفض وجود نقل نشط غير محسوم.
