On-screen writing
Fixed generation directions prohibit captions, lettering and logos. Native
video/audio markers are disabled. Instructions alone cannot guarantee compliance.
After rendering, a CPU-only multiscale detector checks every decoded frame.
Captioned results enter needs_review and are not accepted as completed scenes;
the automatic film chain stops without another paid generation.
Raw MP4 and cloud success are preserved independently from local quality status.
Clean results retain the original audio bitstream and last-frame continuation.
OCR cannot prove absence of every decorative/vertical/tiny glyph. Review remains
necessary. Small clothing-button detections are excluded using documented shape
criteria, which can also miss short decorative marks; this is not a guarantee.

CPU repair is EXPERIMENTAL, OFF in production. Initial Telea tests smeared the
tray and missed background lettering. OpenCV LaMa proved too slow in the full
clip test, which was stopped locally. Do not publish those experimental clips.
The --repair-text option exists for explicit offline investigation only, never
for automatic paid retries. It can affect image details and temporal consistency.
No external voice engine, paid cloud job or new GPU was used in this change.

Server prerequisites before rollout
Create a separate CPU Python environment using engine/text-requirements.lock.
ENGINE_TEXT_QC_PYTHON must be its absolute Python executable path.
ENGINE_TEXT_DETECTOR_MODEL points to the pinned Tiny detector below.
RapidOCR's packaged Small detector is hash-verified too.
ENGINE_FFMPEG_BIN can select the installed CPU ffmpeg executable.
The worker receives only a small OS/model-path environment allowlist, no keys.
CPU worker deadline is 900 seconds, with scoped process-tree cleanup.
The backend must be deployed with both detector files before startup quotes pass.
Do not activate an old Conv session after the quality contract changes.
